# Fileclass: key features and technical design

**Verification, 3 October 2026.** This reference uses the official [Fileclass documentation](https://mdelobelle.github.io/fileclass/), the author's [repository](https://github.com/mdelobelle/fileclass), and the latest stable public [release, `0.2.15`](https://github.com/mdelobelle/fileclass/releases/tag/0.2.15) (17 August 2026). The tagged [`manifest.json`](https://github.com/mdelobelle/fileclass/blob/0.2.15/manifest.json) requires Obsidian `1.12.7` or newer and supports desktop and mobile. The README recommends the core Bases plugin, Obsidian's tool for filtering and displaying notes. Schemas and typed input still work without Bases, but features that query or display its views need it. Four commits on `main` postdate this release. Source claims below use tag `0.2.15`, commit `9a1d7a9`. This review checked documentation and source, not a live Obsidian vault. Behavior that depends on Obsidian's undocumented internal code remains a limit. [Repository README](https://github.com/mdelobelle/fileclass/blob/0.2.15/README.md) · [Release](https://github.com/mdelobelle/fileclass/releases/tag/0.2.15)

Fileclass is an Obsidian community plugin that gives Markdown notes reusable, typed fields. Markdown is plain text with simple formatting. The fields sit in *frontmatter*: YAML key-and-value text between `---` lines at the top of a note. Obsidian shows this data as **Properties**. A *fileClass* defines the fields and the ways notes acquire them. This reference links visible actions to stored data for later reuse decisions. [Fileclass schema guide](https://mdelobelle.github.io/fileclass/schema/) · [Obsidian Properties](https://obsidian.md/help/properties)

## Key features and functionality

**Class schemas.** A schema is a reusable plan for a note's fields. Set **Class files folder**, then create or edit a class note with commands, its context menu, or the schema editor. The editor adds, removes, reorders, and changes typed fields without hand-writing YAML. A class note's frontmatter stores the definition. Without a configured class folder, Fileclass commands refuse to run. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#fileclass-notes)

**Note binding.** Add a class to one note with a command or Properties action, or let a class claim notes through a tag, folder path, or bookmark group. A note may carry several classes, and the global class setting can add a common baseline. Explicit assignment writes the configurable `fileClass` property; tag, folder, bookmark, and global assignment need no `fileClass` line on the note. Binding a class normally inserts its missing fields, but this can be disabled. Applies to `0.2.15`; see the Base-view binding discrepancy below. [Documented](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)

**Guided editing.** The note-fields modal lists the note's class fields, values, and class origins. Type-aware controls also appear in Obsidian's Properties panel, context menus, a command for the field at the editor cursor, and Fileclass's editable table. A `Cycle` click advances its value; a Boolean click flips it; other clicks open the relevant picker or form. Optional indicators appear beside note names and links; these and the Properties buttons depend on Obsidian's screen structure, so they may break after UI changes. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/ui/)

**Value choices.** `Select`, `Cycle`, and `Multi` offer values from a list in the class, non-empty lines of another note, or a `.base` view. A `.base` view is a saved way to list notes with optional filters and columns. It may supply file names or distinct column values in view order; an unavailable source leaves free entry. File and Media pickers use a Base view for candidate files, or fall back to all notes or media. A link field can narrow candidates using another saved field, but changing that source does not clear an old selection. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/fields/#where-allowed-values-come-from) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/valuesIo.ts)

**Quality checks.** Any field can be marked `required`; missing or wrong-type values then appear as violations in the note or editable table. They also appear through the API (functions other programs can call) and CLI (a terminal command tool). Saving a note is not blocked, so validation reports problems rather than preventing manual edits. The API's `setValue` and bulk-set methods reject invalid entries; a missing choice list removes choice restrictions, and custom date formats receive limited checks. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/fields/#required-fields) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/validate.ts)

**Note creation.** A class can offer several `newNotes` destinations, each with a folder and template; one destination needs no extra choice. Creating a note applies its template first, then merges the explicit `fileClass` binding and missing fields into frontmatter, keeping values the template supplied. Fileclass uses Templater when installed, otherwise the core Templates substitutions, and does not manage the note body beyond applying that template. New notes from a filtered table can receive values fixed by its filter, and notes from a reverse relation can receive the link back to the current note. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#creating-a-note-with-a-class)

**Bulk changes.** Commands insert missing fields across every note a class claims, or set one field on a filtered set of notes. Bulk editing shows a preview with each old and new value and lets the user exclude rows before applying. Renaming a field offers a separate migration of existing note keys and skips notes that already contain the new key. A reorder command places declared frontmatter fields in class order while retaining undeclared keys, though rewriting YAML can remove comments. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/ui/#bulk-edit-set-where) · [Documented](https://mdelobelle.github.io/fileclass/schema/#renaming-a-field) · [Documented](https://mdelobelle.github.io/fileclass/fields/#the-order-of-a-notes-properties)

**Bases views.** Fileclass can create a `.base` file and a managed view for one class, with fields as columns and a filter for explicit classes, folders, and tags. Sync from a changed class to its view is **one-way and manual**; user-made views and most tuning survive. It registers `fileclass-table`, whose note property cells use Fileclass editors and whose optional `valid`/`errors` columns show violations. The table draws every row, even those off screen, so very large views can be slow; Bases must be enabled. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/views/#generating-a-base) · [Documented](https://mdelobelle.github.io/fileclass/views/#editable-table-view)

**Reverse relations.** A Base-backed File or Media link field can be shown from the target note by creating or adopting a filtered view and embedding it. The class records each association as `relatedViews: [{field, view}]`, where `view` uses `Base.base#View` syntax. The embedded view uses `this.file` for the host note, so one view can serve many notes; a list-valued link uses a membership filter. Nested links and link fields with no candidate Base do not qualify. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/views/#the-other-end-of-a-relation)

**Canvas model.** A `.canvas` file is Obsidian's visual board of boxes and links. A command draws classes, inheritance, bindings, and file dependencies on one board. Later updates require a command and keep the positions of recognised boxes. Separately, enabled Canvas fields automatically read a chosen board and write links or group names into note frontmatter when the board changes. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/views/#the-schema-canvas) · [Documented](https://mdelobelle.github.io/fileclass/fields/#canvas-fields-canvas--canvasgroup--canvasgrouplink)

**Programmatic access.** The API at `app.plugins.plugins.fileclass.api` lets other programs inspect classes, explain notes, check values, and make validated writes. It returns JSON, a common structured-text format. The separate `fileclass-cli` tool offers terminal commands and an interactive text interface for inspection, validation, and editing. It uses `obsidian eval`, so Obsidian and Fileclass must be running; `set-where` previews changes unless given `--apply`. Applies to `0.2.15`; the API version mismatch is noted below. [Documented](https://mdelobelle.github.io/fileclass/cli/) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/api/fileclassApi.ts)

## Data model and binding rules

**Definition file.** A fileClass is a normal `.md` file under `classFilesPath`, with a YAML `fields` list. Its name comes from the path below that folder: `Book.md` → `Book`, but `Sub/Book.md` → `Sub/Book`. Each field entry has `name`, stable `id` (a lasting identifier), `type`, `options`, and `path`. A root field uses `path: ""`; nested fields join parent IDs with `____`. Other class options include `extends`, `excludes`, `mapWithTag`, `tagNames`, `filesPaths`, `bookmarksGroups`, `newNotes`, `relatedViews`, `baseFile`, `baseView`, `fieldsOrder`, and `icon`. The reader reports malformed entries without stopping, and treats an unknown type as `Input`. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#fileclass-notes) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileClass.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/field.ts)

```yaml
# Classes/Book.md
---
extends: Media
filesPaths: [Books]
fields:
  - name: status
    id: status01
    type: Select
    options:
      sourceType: ValuesList
      valuesList: {"1": Reading, "2": Read}
    path: ""
---
```

The example's `id` illustrates the required stable identifier; the editor generates real IDs. A note explicitly bound to the class can then contain `fileClass: Book` and `status: Reading`. A note in `Books/` may contain only `status: Reading`; its class comes from `filesPaths`, not a written assignment. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)

**Inheritance order.** `extends` names one parent class and stops if the chain loops back on itself. Fileclass starts with the oldest ancestor's fields and works toward the child. A nearer class replaces a field with the same name at the same level; `excludes` drops inherited root fields. A class can set its own field display order in `fieldsOrder` without changing the parent. These rules change the fields offered to notes, but do not rewrite stored values. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#inheritance) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/inheritance.ts)

**Binding precedence.** Fileclass collects the note's `fileClass` values first, then tag, folder, and bookmark matches; it keeps each class's first occurrence. Tags can come from the body or frontmatter, ignore letter case, and match parent tags (`#author/french` also matches `author`). A global class goes first as a baseline, except on class-definition notes. When classes share a field, the **last** collected class defines it: `Article` wins over `Book` in `fileClass: [Book, Article]`. A later tag or folder match can likewise override an explicit class, although the guide calls explicit binding “first priority.” The note still has one YAML key for that field; its class field ID is not stored there. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)

**Settings location.** Obsidian saves plugin-wide settings through `loadData`/`saveData`, normally in `.obsidian/plugins/fileclass/data.json`. Class definitions and note values stay in vault Markdown files. Settings cover folders, the binding key, the global class, date formats, editor controls, the Canvas engine, and log limits. Fileclass rebuilds its class and bookmark lookup maps in memory rather than saving a separate database. When enabled, the schema log lives at `<class folder>/fileclass.log`, with older logs under `.logs/`. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/settings/) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/settings/settings.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)

## Field types and storage

The 26 usable types below come from the [official field guide](https://mdelobelle.github.io/fileclass/fields/#available-field-types). “Scalar” means one YAML value; “list” means several values in order. The main validation check accepts a missing, `null`, or empty-string value unless the field is `required`. Applies to `0.2.15`. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/validate.ts)

| Types | Stored in note frontmatter | Main definition or behavior |
| --- | --- | --- |
| `Input`, `MultiInput` | Text scalar; list of text | Optional `template` creates guided placeholder inputs; `multiline` gives a textarea and writes line breaks as YAML text. |
| `Number`, `Boolean` | Numeric scalar; `true`/`false` | Number options `min`, `max`, `step`; an empty Boolean is distinct from `false`. |
| `Select`, `Cycle`, `Multi` | One allowed scalar; one cycling scalar; list of allowed scalars | `options.sourceType` selects inline, note, or Base values. `Cycle` advances on click; `Multi` stores class source order. |
| `Date`, `DateTime`, `Time` | Text/date scalar, or an Obsidian link such as `[[Daily Note]]` when configured | `dateFormat` controls what is **written**; defaults are `YYYY-MM-DD`, `YYYY-MM-DDTHH:mm`, `HH:mm`. `defaultInsertAsLink` and `dateLinkPath` control links. |
| `Duration`, `CycleDuration` | Standard time-span text (RFC 5545), such as `PT1H30M`; ordered list of these values | `presets` offer quick picks. A Date/DateTime's `nextIntervalField` can advance from one Duration or rotate a CycleDuration list on a manual action. |
| `Location`, `Icon`, `Color` | `"lat,lon"` text; bare icon ID; web-style color text (CSS) | Coordinates are range checked. Icon and color pickers offer registered icons or palettes; the stored value remains a plain scalar. |
| `File`, `MultiFile`, `Media`, `MultiMedia` | Link text; list of links | `baseFile` + `viewName` source candidates; optional `displayColumn` sets alias. Media adds image thumbnails; links follow the vault's link format and are not embeds. |
| `Object`, `ObjectList` | Nested YAML key-and-value group; list of those groups | Child field definitions use `path`; editor validates declared children and keeps undeclared keys. `displayTemplate` changes the shown summary, not storage. |
| `YAML`, `JSON` | Parsed YAML key-and-value structure; JSON **text** (another structured-text format) | Both have text editors. Bases can read inside YAML; JSON text keeps its formatting but is seen as one value. |
| `Canvas`, `CanvasGroup`, `CanvasGroupLink` | Auto-filled list of links; list of group names; list of links | `canvasPath`, direction, and edge/node/group filters determine values. The Canvas engine writes these when the graph changes. |

**Choice encoding.** An inline choice list uses `sourceType: ValuesList` and stores choices under `options.valuesList`, for example `{"1": "Reading", "2": "Read"}`. Fileclass also reads an older numbered record or a plain array. `ValuesListNotePath` points to another note with `valuesListNotePath`; `ValuesFromBase` uses `baseFile`, `viewName`, and optional `valuesColumn`. If a list resolves to values, `Select`, `Cycle`, and each `Multi` item must match one. If it resolves to nothing, Fileclass allows free text. Existing invalid note values remain until edited and show up in validation. Applies to `0.2.15`. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/options.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/valuesIo.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/validate.ts)

**Empty insertion.** “Insert missing fields” writes root keys only: most scalar types become `""`, list types `[]`, and `Object`/`YAML`/`JSON` start as `{}`. It does not invent a Boolean `false`, a number zero, or a field's first allowed choice. A required field inserted empty still fails validation. A template may supply an actual starting value before missing keys are filled. Applies to `0.2.15`. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/support.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/commands/insertMissingFields.ts)

## Writes, runtime, and portability

**Frontmatter lifecycle.** Most reads use Obsidian's metadata cache, its index of parsed note data. Most writes use the `processFrontMatter` API to edit YAML without reading the note body. Fileclass finds a note value by its field name, or its nested names, rather than by field ID; clearing a value removes its key. The choice list shown while typing YAML in Source mode is an exception: it edits the open text buffer so unsaved typing is not lost. Manual changes become visible when Obsidian refreshes its cache, but Fileclass does not automatically fix invalid values. Applies to `0.2.15`. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/io/read.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/io/write.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/ui/frontmatterSuggest.ts)

**Index refresh.** Fileclass scans Markdown files under the class folder and builds class, inheritance, tag, path, and bookmark lookup maps in memory. It rebuilds after Obsidian finishes reading note metadata or a vault file changes, waiting briefly to group rapid events. A `.base` change clears stored query results. A rebuild sends `fileclass:indexed` to other parts of Obsidian. Bookmark binding reads the Bookmarks core plugin's internal data, and Bases access goes through a connector in Fileclass's code. These are live connections, not data written into each note. Applies to `0.2.15`. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/main.ts)

**Path changes.** Class definitions store paths to notes, Bases, Canvas files, and folders as plain strings. On an observed rename Fileclass warns but does not rewrite those definitions; a startup or manual sweep finds references broken while Fileclass was off. A schema log can keep these findings and records of bulk/schema operations. Separately, a field-name rename can migrate the corresponding YAML keys after a user preview. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/schema/#when-something-a-fileclass-points-at-moves)

**Plugin removal.** Note values stay in ordinary Markdown and YAML: numbers, true/false values, lists, nested groups, and quoted links remain readable without Fileclass. Class definitions also remain Markdown. Their `fields` and binding rules need Fileclass or another reader to restore typed forms and validation. Generated `.base` files remain separate vault files. Fileclass reads existing Metadata Menu class definitions, but ignores old options for Dataview, another note-query plugin. It does not support Dataview's inline `key:: value` fields. Applies to `0.2.15`. [Documented](https://mdelobelle.github.io/fileclass/positioning/) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileClass.ts)

## Verified limits and source discrepancies

- **Base-view class binding.** The schema guide lists class assignment through a Base view. In `0.2.15`, the inspected class index supplies no `baseViewNames` to the binding resolver, and class options have no binding-view setting. The resolver can accept such matches, but repository search found no caller that gives them to it. Automatic class assignment through a Base view is therefore unverified for this release. Base-backed value pickers and bulk filters are separate, implemented features. [Documented claim](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts)
- **Collision order.** The schema guide calls `fileClass` binding the highest-priority source. The resolver checks it before tags, paths, and bookmarks, yet the **last** class defining a field wins when fields are combined. A later automatic binding can therefore supply the field's type and options. Here, “priority” in the guide describes collection order, not which field definition wins. [Documented claim](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts)
- **Nested class names — guide simplifies path behavior.** The guide says a class name is its note's filename. The tagged parser actually uses the whole path below the class folder, so a nested class note has a slash-containing name. How the schema editor handles hand-created nested class notes was not tested live. [Documented claim](https://mdelobelle.github.io/fileclass/schema/#fileclass-notes) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileClass.ts)
- **Computed types — legacy recognition only.** The guide says 26 usable types and excludes `Lookup` and `Formula`. The parser recognises their names for compatibility, but the tagged source does not provide their computed input behavior; Bases formulas and reverse views are the current alternatives. A resolver branch for global “preset fields” is likewise not supplied by settings or the index. [Documented](https://mdelobelle.github.io/fileclass/fields/#available-field-types) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/field.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)
- **API version and write path — documentation lags code.** The CLI page says `api.version` is `1.0`, while tag `0.2.15` sets `API_VERSION = "1.1"`. Broad documentation says writes use `processFrontMatter`; source-mode choice completion instead writes through `editor.replaceRange`, and optional reorder after missing-field insertion can require a second frontmatter write. [Documented claim](https://mdelobelle.github.io/fileclass/cli/#public-api) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/api/fileclassApi.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/ui/frontmatterSuggest.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/commands/insertMissingFields.ts)
- **Selective validation.** The main validator accepts text that looks like a number or `"true"`/`"false"` in Number and Boolean fields. It accepts any nonempty custom-formatted or wikilink-shaped date. The `required` check counts `[]` and `{}` as present; only a missing, `null`, or `""` value is empty. It also accepts one value instead of a list for `Multi` and `MultiInput`. It flags that shape for `MultiFile` and `MultiMedia`, because Bases filters can skip a single link. These rules matter for older or manually edited notes. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/fields/validate.ts) · [Documented](https://mdelobelle.github.io/fileclass/views/#one-value-written-without-a-list)
- **Runtime limits.** Bases is needed for value-source views, generated views, and `fileclass-table`. The editable table draws every row, so very large results may be slow. Obsidian gives each property name one native type across the vault and cannot directly edit nested values. Its own Date picker can overwrite a Fileclass date format. Future changes to Obsidian's interface or internal code were not tested live for this reference. [Documented](https://mdelobelle.github.io/fileclass/views/#editable-table-view) · [Documented](https://mdelobelle.github.io/fileclass/fields/#obsidians-own-property-type-can-overwrite-your-format) · [Obsidian Properties](https://obsidian.md/help/properties)

**Assumptions and remaining uncertainty.** “Current” means the stable public release found on 3 October 2026. It excludes newer, unreleased code on the repository's `main` branch. The Base-view binding finding comes from source inspection, not a live test. The document does not assume automatic default values, automatic repair of invalid notes, or an offline CLI. It also does not assume that dependent choices update stored values when their source field changes.

## Binding Precedence — Expanded Detail

A class is **bound** to a note when Fileclass applies that class's fields to the note. A note can name one class with `fileClass: Book` or several, in order, with `fileClass: [Book, Article]`. The `fileClass` key can be changed in plugin settings; the source also accepts a comma-separated string. Classes can claim notes through tags (`mapWithTag`, `tagNames`), folders (`filesPaths`), or bookmark groups (`bookmarksGroups`). A setting can add one global class. Only explicit assignment writes the class name into the note's YAML; the other bindings are calculated from the note and settings. Names that match no existing class are ignored. [Documented](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileClass.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts)

Fileclass collects explicit `fileClass` names first, in their written order. It then collects tag matches, folder matches, and bookmark-group matches. Tags are visited in the order Obsidian supplies them, with a full nested tag tried before its parents. Folder mappings follow their stored order; bookmark paths follow the order gathered from the Bookmarks plugin. If a class appears twice, Fileclass keeps its **first position and first binding reason**. For example, an explicit `Book` keeps its position among the note's classes even if a tag also matches `Book`. Each exact tag, folder, or bookmark mapping points to one class. If two classes define the same mapping, the later indexed one holds that mapping; an already collected class is unaffected. [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts)

Tag binding reads tags in the note body and in frontmatter through Obsidian's index of note metadata. `mapWithTag: true` makes the class's own name a matching tag; `tagNames` adds more. Matching ignores letter case. A class name or configured tag containing a space cannot bind this way. A note tagged `#author/french` can match classes mapped to both `author/french` and `author`, with the more specific match tried first. The `filesPaths` setting matches the note's parent folder by a literal text prefix: `Books` can therefore also match `Bookshelf`. Bookmark binding uses the Bookmarks core plugin; a note in `Films/Tarkovsky` can match a class mapped to the parent `Films` group. [Documented](https://mdelobelle.github.io/fileclass/schema/#binding-a-note-to-fileclasses) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/fileclassIndex.ts) · [Source verified](https://github.com/mdelobelle/fileclass/blob/0.2.15/src/schema/resolver.ts)

The global class goes **at the front** of the list if it exists and has not already been collected. It gives ordinary notes a baseline, even when they have other classes. It does not apply to class-definition notes. If another binding already collected the global class, that first position is kept instead. Fileclass then combines the fields in list order. For the same root field name, the **last class** supplies the field's type and options. Thus `fileClass: [Book, Article]` makes `Article`'s `publisher` definition win over `Book`'s. A later folder-bound `LibraryItem` could override it again. A root `publisher` and `editions.publisher` are different fields. Nested children also need the same internal parent-ID path to count as the same field. The documentation calls explicit `fileClass` binding “first priority.” The source confirms that Fileclass **checks it first** and keeps that reason when the same class matches twice. For a field shared by different classes, however, the **last collected class** supplies its definition. These are two meanings of priority: which binding is recorded first, and which field definition wins. A tag-, folder-, or bookmark-bound class can therefore override a field from an explicit class. The winner changes Fileclass's input and validation rules, but binding alone neither creates two `publisher:` keys nor rewrites a value already stored there. Stable field `id` values belong to class definitions for ordering and nesting; the note stores one value under the field name. The guide also lists Base-view class binding, but the inspected index supplies no such matches to the resolver.
