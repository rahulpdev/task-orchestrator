# Conditional Properties: key features and technical design

**Verification (3 October 2026).** This reference covers Diego Eis's **Conditional Properties 0.26.0**, the latest stable GitHub release checked that day. The [release](https://github.com/diegoeis/obsidian-conditional-properties/releases/tag/0.26.0), [manifest](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/manifest.json), and [version map](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/versions.json) specify **Obsidian 1.5.0 minimum** and mobile support (`isDesktopOnly: false`). Sources are the maintainer's [documentation site](https://diegoeis.github.io/obsidian-conditional-properties/), [tagged README](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/README.md) (the project's introduction), [changelog](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/CHANGELOG.md), and [shipped code](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js). The `{{match}}` feature is marked **Beta**, meaning still experimental, even in this stable release. This review did not test the plugin in a live Obsidian vault (folder of notes) or on different devices.

Conditional Properties is an Obsidian plugin that runs **IF/THEN rules** on Markdown notes, which are plain-text files. It can change frontmatter (the YAML property block at the top of a note), the first `#` heading, file names and folders, and bookmarks. YAML is the plain-text format Obsidian uses to store note properties. This reference explains both what users configure and how the plugin stores and applies those rules. All feature descriptions below refer to **v0.26.0**, unless stated otherwise.

## Key features and functionality

**Scheduled scans.** The plugin checks notes every five minutes or longer, and a changed interval takes effect at once. Users can also run all rules, one rule, or the active file by command. A scan can cover the whole vault (Obsidian’s folder of notes) or the newest 1–1000 notes by creation or edit time; the default is 15. Stop finishes the current file and skips the rest. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/execution-scheduling.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L78-L102), [scan selection](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L250-L330). **v0.26.0.**

**Property edits.** A matching rule can **Add value**, **Remove value**, **Overwrite all values with**, **Delete property**, or **Rename property to**. Add splits text at commas and can turn one existing value into a YAML list. Overwrite stores its text as one value, even if it contains commas. Remove deletes matching values; Delete removes the whole property; Rename moves a value to a new name only when that name is absent. These edits stay in the note’s YAML after the plugin is disabled. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/actions/property-actions.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L568-L692). **v0.26.0.**

**Heading edits.** **First level title** actions add a prefix, add a suffix, or overwrite a note’s first `#` heading (also called an H1). This heading must be at the start of the note body, after any YAML block. Prefix and suffix need an existing H1; Overwrite can create one. These actions change Markdown text, not YAML or the filename. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/actions/first-level-title-actions.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L528-L565), [heading writer](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1588-L1640). **v0.26.0.**

**File actions.** **Note file** actions can rename a file, add a name prefix or suffix, move it, bookmark or unbookmark it, or delete it. Rename keeps the file extension; Move can create a missing destination folder inside the vault. Obsidian’s file manager handles renames and moves so links to the file can update. Delete follows Obsidian’s trash setting and stops further actions on that file. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/actions/note-file-actions.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L695-L790). **v0.26.0.**

**Settings portability.** The plugin keeps rules and scan settings in its own `data.json`, under `.obsidian/plugins/conditional-properties/`, apart from note YAML. Export writes `conditional-properties-settings-YYYY-MM-DD.json` to the vault root; JSON is a plain-text format for structured settings. Import reads such a file and updates older rule formats. A search box filters the rules shown in settings but does not change which rules run. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/backup-restore.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L12-L33), [import/export](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1820-L1920). **v0.26.0.**

## Conditions and rules

**Rule shape.** Each saved rule has a flat `conditions[]` list, an ordered `thenActions[]` list, and `match: "any"` or `"all"`. A condition stores `ifType`, `op`, `ifValue`, and, for a property, `ifProp`. “Any” means one condition may match; “All” means every condition must match. Negative operators provide exclusions, but there are no nested groups, rule priorities, or inherited rules. The README’s IF/THEN examples show the settings screen; they are not the saved JSON rule format. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/conditions/multiple-conditions.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L392-L528), [settings builder](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L2300-L2470). **v0.26.0.**

**Property tests.** **Property** conditions check a named key in the note’s YAML, including `tags` when it appears there. They offer `exactly`, `contains`, `notContains`, `exists`, `notExists`, and `isEmpty`. Text matching is case-sensitive; for a list, `exactly` and `contains` need one matching item, while `notContains` needs every item to miss. An empty value still `exists`; `isEmpty` does not match a missing key. Tags written as `#tag` in the note body are not checked. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/conditions/property.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1209-L1295). **v0.26.0.**

**Title tests.** **First level title** checks the first actual H1 at the start of the note body. It uses the same six operators as **Property**. `notExists` and `isEmpty` both match a missing H1; a later H1, the filename, and Obsidian’s displayed inline title do not count. The plugin usually reads Obsidian’s heading index and reads the file directly when that index cannot answer. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/conditions/first-level-title.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1497-L1587). **v0.26.0.**

**File tests.** **Note file** checks a file’s name or parent folder. It stores one of `filenameContains`, `filenameNotContains`, `filenameExactly`, `parentFolderIs`, or `parentFolderIsNot`. Filename checks ignore `.md` and ignore case. Folder checks also ignore case; they match a folder name or adjacent path segments anywhere in the parent path. These checks have no `exists` or `isEmpty` operator. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/conditions/note-file.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1400-L1490). **v0.26.0.**

**Regex tests.** Wrap a value as `/pattern/flags` to use a regular expression: a text pattern that can match many strings. This works for properties, H1 titles, and filenames, but not folders. Regex matching is case-sensitive unless it has the `i` flag; `exactly` still matches anywhere unless the pattern uses `^` and `$` to mark its ends. Bad patterns fail to match and raise one notice per distinct pattern. The plugin saves compiled patterns in memory so it can reuse them during scans. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/conditions/regex-matching.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1209-L1375). **v0.26.0.**

**Rule interaction.** Rules run in saved order. A later rule can see property edits, file renames, and file moves made by earlier rules in the same scan. A rule does not undo an old edit when its condition stops matching. The settings screen shows the rules in **reverse** saved order, however, so the top displayed rule runs last. That display order conflicts with the README’s claim that rules run in the order shown. [Documented](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/README.md#L374-L383); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L392-L692), [display order](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L2220-L2230). **v0.26.0.**

## Property behavior and stored data

**Typed values.** The plugin checks Obsidian’s property type and gives `checkbox`, `date`, and `datetime` special treatment. These hold one value, so **Add value** acts like Overwrite: only text `"true"` becomes YAML `true`, while every other checkbox input becomes `false`. It converts recognized dates to `YYYY-MM-DD`, but leaves unrecognized dates as text and only trims datetime input. Date parsing tries the Daily Notes format, the Templates format, then `DD-MM-YYYY`, `DD/MM/YYYY`, and `YYYY/MM/DD`. Plain-text IF values go through the same conversion; regex patterns do not. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/typed-properties.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1643-L1770). **v0.26.0.**

**Value boundaries.** The plugin has no verified single- or multiple-choice menu, required-value rule, empty-value rule, conditional property display, or check that rejects invalid values. A `notExists` condition plus Add or Overwrite can fill a missing value once, but it does not prevent later edits. Different rules may write different values to one property, yet they do not limit what someone can type in Obsidian. Number, link, text, and tag properties receive ordinary text from actions, with no special number or link processing. Existing values are not flagged as invalid; `null` means a present but empty YAML value and differs from a missing key, but there is no action for setting it directly. [Source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L568-L692), [type coercion](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1643-L1779), [settings controls](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L2856-L3000). **v0.26.0.**

**YAML mapping.** Suppose `status` is `done` and a rule says to overwrite `completed` with `"true"`. A matching scan writes `completed: true` if Obsidian recognizes `completed` as a checkbox property; otherwise it writes text. A folder condition such as **Parent folder is** `Archive` can instead trigger an action that writes `stage: archived`. The folder path decides whether the rule runs, but only the action changes YAML. Removing the plugin leaves those edits in the note, while rules remain in plugin settings. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/actions/property-actions.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L392-L692), [writer](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1771-L1784). **v0.26.0.**

## Technical design and conventions

**Scan runtime.** At startup, the plugin loads settings, updates older rule formats, and starts one timer. For each Markdown file in scope, it reads frontmatter from Obsidian’s `metadataCache`: an index of note properties and headings. It copies that data, runs the rules, and writes any changes. It does not listen for Obsidian’s file-change notifications, so new or edited notes wait for the next timed or manual scan. It keeps text patterns in memory for reuse, but no separate saved index of notes. [Source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L12-L102), [scan path](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L250-L392), [evaluation](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L392-L692). **v0.26.0.**

**Write timing.** File moves, renames, deletions, and bookmark changes happen as their actions run. Property changes wait in a copy of frontmatter until all rules finish, then `processFrontMatter` writes them to YAML. H1 changes also wait; `vault.process` writes them to Markdown, separately from YAML. If a file is deleted, those pending writes are skipped. Overwrite can write the same YAML value again on later scans. The plugin allows one scoped scan at a time and checks Stop between files. [Source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L250-L392), [evaluation](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L392-L692), [writer](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1771-L1784). **v0.26.0.**

**Dynamic text.** IF values and most THEN text fields can use placeholders: tokens replaced when a rule runs. Examples include `{{date}}` or `{{today}}` for today, `{{created_date}}` for file creation date, `{{updated_date}}` for edit date, `{{filename}}` or `{{title}}` for the file’s name, and `{{propertyName}}` for a YAML value. `{{yesterday}}`, `{{tomorrow}}`, and `{{time}}` also work; date and time tokens accept `:FORMAT`. Missing properties become empty text, and lists become comma-separated text. Older single braces still work, but `{date}` means file creation date while `{{date}}` means today; bare date tokens in Note file fields use `YYYY-MM-DD`. IF regex values are not expanded; the Beta `{{match}}`, `{{match:N}}`, and `{{match:name}}` tokens reuse a matching pattern’s result in THEN text, except for list-valued properties. [Documented](https://diegoeis.github.io/obsidian-conditional-properties/placeholders.html); [source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L994-L1207), [regex capture](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1375-L1402). **v0.26.0.**

**Obsidian coupling.** The plugin uses Obsidian’s file tools to change notes and update links after file moves. For some features it also reads undocumented Obsidian internals: property types, Daily Notes and Templates date formats, vault date settings, and the Bookmarks data tree. “Undocumented” means Obsidian does not promise those details will stay the same. Bookmark actions need Obsidian’s core Bookmarks plugin and are skipped when it is unavailable. Scans sort all Markdown files for the “latest” scopes and process one file at a time; the source gives no measured limit for large vaults. [Source verified](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L695-L930), [type/date APIs](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1643-L1770); [Obsidian Vault API](https://docs.obsidian.md/Reference/TypeScript%20API/Vault). **v0.26.0.**

## Limitations and evidence notes

- **Docs and code.** The main features agree, but the rule display order conflicts with the described run order. The README shows some examples with older single-brace placeholders; current documentation prefers double braces, and the code accepts both. IF/THEN examples describe the settings screen, not a YAML rule format. [README](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/README.md); [changelog](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/CHANGELOG.md#L60-L76).
- **Code edge cases.** Add checks list entries by stored type, so number `1` and text `"1"` can both appear. When several H1 actions match, each starts from the original H1; only the last pending result is written. These are findings from the code, not promises in the documentation. [Property loop](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L580-L610); [title loop](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L528-L565).
- **Imported interval.** Import changes saved scan settings, and its message says the plugin will reload. The code does not reload it or restart the timer there. An imported interval therefore appears to take effect only after a direct interval edit or plugin reload; this was not tested live. [Import handler](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1872-L1920); [timer setup](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L78-L102).
- **Untested behavior.** This review did not measure how soon Obsidian indexes edits made outside the app, how renames fail on different devices, or how fast large vaults scan. It also did not test bookmarks against future Obsidian versions. The code reads the file directly when the H1 index cannot answer, while property conditions use the indexed copy. [Scan source](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L250-L392); [heading fallback](https://github.com/diegoeis/obsidian-conditional-properties/blob/0.26.0/main.js#L1497-L1587).
